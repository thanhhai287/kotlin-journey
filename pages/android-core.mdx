# Android — học sâu trên app đang chạy

Android là **hướng chính** cùng game server, dùng Kotlin/Java làm nền. Bắt đầu từ [A01–A05](/phase-1) trên app Kho đồ; nối server sau khi state và dữ liệu cục bộ đã rõ. Không giới hạn Android thành một client demo 16h như lộ trình cũ.

## Câu hỏi nền tảng cần trả lời bằng app

| Khi app gặp | Học kỹ phần nào | Bằng chứng |
|---|---|---|
| UI hiện sai dù dữ liệu đúng | State, sự kiện, nguồn dữ liệu, recomposition | Tái hiện, chỉ ra state nào sai, test hoặc case hồi quy |
| Xoay màn hình mất form | Lifecycle và state holder | Kiểm configuration change; giải thích state sống ở đâu |
| Mở lại app mất dữ liệu | Saved state khác persistence, process lifetime | Kiểm mở lại/process recreation riêng với xoay màn hình |
| Rời màn hình vẫn nhận kết quả cũ | Scope, cancellation, coroutine ownership | Log vòng đời tác vụ và case tái hiện |
| Mạng chậm, lỗi hoặc mất mạng | Loading/error/retry, nguồn dữ liệu, response cũ | UI có phản hồi rõ; retry không nhân đôi thao tác |
| Cuộn/nhập bị đứng | Main thread, I/O, allocation, profiling | Quan sát bằng công cụ rồi sửa một nguyên nhân và đo lại |
| Người khác dùng app không hiểu | Form, label, điều hướng, trạng thái rỗng/lỗi, accessibility | Thử màn hình nhỏ/chữ lớn và một người dùng thật |

## A06–A07 — từ app cục bộ tới dữ liệu trên server

[Đề cương Google](https://developer.android.com/courses/android-basics-compose/course) đặt kết nối mạng ở unit 5 và lưu dữ liệu ở unit 6. Chương trình chọn thứ tự đó cho phần HTTP/SQL/Room; không yêu cầu làm lại mọi app mẫu của khoá.

| Ticket / tiên quyết | Yêu cầu | Nghiệm thu |
|---|---|---|
| **A06 — sau A05, cùng S01 rồi S02** | Đọc kho từ API thật; có loading/rỗng/lỗi; sau đó gửi một thay đổi và nhận kết quả | Tắt mạng, response chậm, chuyển màn hình và tải lại có case; kết quả cũ không ghi đè dữ liệu mới; phân biệt lỗi transport và lỗi server trả về |
| **A07 — sau A06 và phần SQL ở S03** | Lưu một bản dữ liệu bằng Room để xem lại khi mất mạng; schema, truy vấn, một lần đổi schema | Khởi động offline có trạng thái rõ; test truy vấn/migration và lỗi tải; server vẫn quyết định dữ liệu nghiệp vụ |

A07 ban đầu chỉ cache để đọc: hiển thị đó là bản đã lưu, không âm thầm cho sửa offline rồi giả báo server đã nhận. Đồng bộ ghi offline là yêu cầu mở rộng sau khi hiểu retry/xung đột. Room dùng SQLite trên thiết bị; PostgreSQL thuộc server, không phải cùng một database.

## Khi nối game server

App là client gửi ý định, server quyết định tính hợp lệ của lệnh game. Một nút bị vô hiệu trên UI không thay được kiểm tra trên server. Viết case gửi lại lệnh, sai lượt, mất kết nối và nhận trạng thái mới sau reconnect.

Đầu tiên làm một flow xuyên suốt: người dùng thao tác → app gửi → server xử lý → app hiển thị. Sau đó mới thêm cache/offline nếu thật sự cần, và ghi rõ dữ liệu nào là nguồn sự thật. Không mặc định thêm repository/use-case cho mọi hàm; ranh giới phải giải quyết một vấn đề test hoặc thay đổi cụ thể.

## Java và Android internals

Đọc/gọi thư viện Java, null interop, equality và resource lifecycle là nội dung chính của [nền Kotlin/Java](/kotlin-java-core). Binder, Zygote, ART, Looper, ANR và memory sâu hơn ở [Android internals](/tham-khao/android-internals): chọn chương khi bug hoặc phép đo cần nó. Không bắt học toàn bộ trước màn hình đầu tiên.

Mỗi vòng học: dự đoán → chạy → quan sát → giải thích → thay điều kiện. Mentor được giải thích cơ chế và cách dùng profiler/debugger; bạn tự viết và kiểm chứng phần đang học.
